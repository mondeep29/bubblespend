## Red test command and failure

`gradle.bat :app:compileDebugAndroidTestKotlin :app:testDebugUnitTest --no-daemon` — **RED**, Gradle 8.9, Microsoft JDK 17.0.20, on `%TEMP%\BT005Project17`. Android test Kotlin compilation failed only because `MainActivity` was not yet implemented, as expected. The home route/heading assertion compiled, and `:app:testDebugUnitTest` passed. Exit code 1. ### Review-fix red and green

- Bundle alias red: `gradlew.bat :app:testDebugUnitTest` failed the new `boundaryCheck_expandsBundleAliasesToForbiddenLibraryCoordinates` regression because `libs.bundles.platform` did not resolve to Room; the two existing architecture tests passed. A second red used a valid multiline TOML bundle array and exposed the same gap (3 tests, 1 failed).
- Bundle alias green: after expanding single-line and multiline `[bundles]` members through `[libraries]` coordinates, `gradlew.bat :app:testDebugUnitTest` passed (25 seconds) and Spotless formatted the changed test. The final full quality rerun passed.

- Theme red: `gradlew.bat :app:connectedDebugAndroidTest` on `BT003_API35_Pixel8 (AVD) - 15`, API 35. The route/heading test passed, while `homeSurface_usesConfiguredLightThemeBackground` failed because no node matched `TestTag = home_surface`. This was captured before adding the production Surface/tag.
- Architecture regression: `gradlew.bat testDebugUnitTest` passed after the test fixture was strengthened. It verifies an innocuous `platform` version-catalog alias resolving to `androidx.room:room-runtime` is rejected, and checks Kotlin, Java, and Groovy sources.
- Post-fix quality: `gradlew.bat spotlessCheck lint testDebugUnitTest assembleDebug` — **PASS**, 70 actionable tasks, using Gradle 8.9, Microsoft JDK 17.0.20, and SDK 35 in `%TEMP%\BT005Project17`.
- Post-fix device test: `gradlew.bat :app:connectedDebugAndroidTest` — **PASS**, 2/2 tests, 0 skipped/failed on `BT003_API35_Pixel8 (AVD) - 15`, API 35. The route/heading and `#FFFBFE` home surface pixel assertions both passed.
- Fresh-copy check: an empty Gradle home downloaded and validated the pinned Gradle 8.9 distribution, but the build daemon was terminated during Android packaging after the JVM failed a native allocation of 57,392 bytes. A bounded-memory retry (`-Xmx768m`, one worker, no parallel execution) produced no task output before the Gradle daemon disappeared; both temporary copies remain preserved. These are environment resource failures, not passing clean-copy builds.
