# BT-020: Measure workflow gate and phase duration

**Objective:** Record workflow gate-call timing and phase visits so later optimization targets measured bottlenecks.

**Dependencies:** BT-019. This task is independent of BT-006 Android/domain files.
**Kind:** foundation. **Risk floor:** elevated because the scripts enforce security and review handoffs.
**Allowed scope:** `workflow/gate.py`, `workflow/transition.py`, workflow evidence templates/docs, and `workflow/tests/test_gate.py` / `test_transition.py`; BT-020 packet and evidence.
**Out of scope:** Android/product code, risk-policy changes, verification-suite selection/caching, research cache, CI/dependencies, and task parallelization.

## Acceptance criteria

- **BT-020-AC-01:** Every production gate evaluation, including a rejected evaluation, writes one record with UTC start/finish, nonnegative monotonic elapsed milliseconds, task ID, gate name, and pass/block/error outcome.
- **BT-020-AC-02:** Successful transitions record ordered phase visits with start and finish timestamps. Rework records a new visit; failed gates and failed state persistence leave task phase history unchanged.
- **BT-020-AC-03:** Timing data contains workflow metadata only. It excludes gate failure text, commands, test output, transaction data, credentials, and arbitrary user strings.
- **BT-020-AC-04:** Existing completed evidence remains readable. Legacy active work may continue with unknown prior timestamps represented as `null`; the implementation must not invent historical times.

## Design constraints

Write gate attempts to per-task `workflow/evidence/BT-NNN-gates.jsonl` so blocked gates are observable without mutating task evidence. Store successful phase visits in `workflow.phaseTimings` in task JSON, updated alongside the queue through the existing rollback-safe transition mechanism. Keep `gate.check()` side-effect free; instrument production CLI and transition gate evaluations. Log only identifiers and outcomes, never failure messages or commands.

## Required tests first

Add failing tests for passing and blocked gate timing records; phase timing across happy path, documentation shortcut, and rework; unchanged history on failed gate or failed second state-file replacement; sanitized log fields; and compatibility with actual legacy BT-005 evidence and active BT-006-shaped evidence without fabricated timestamps.

Record the exact red command and output before implementation. Builder must not edit Tester-owned tests or this plan.

## Recovery

Restore only BT-020-owned workflow scripts, docs/templates, tests, and task evidence. Preserve BT-006 files and evidence. A gate timing record may truthfully remain after a state-write failure; it records the gate evaluation outcome and must not imply that the transition committed.
