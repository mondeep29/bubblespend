# BT-006: Implement money and time primitives

**Objective:** Correct, pure Kotlin money and reporting-period types.

**Inputs:** ADR-003, glossary, D-02/D-05 decisions. **Allowed scope:** core money/time/ID abstractions and unit tests. **Out of scope:** UI, Room, analytics screens.

**Required tests first:** Zero/negative/overflow/precision/currency mismatch; locale parsing; midnight/month/year/leap/DST boundaries; prior equivalent period; injected Clock/UUID/timezone. Record red output.

**Acceptance:** No financial binary floating point; UTC storage and `[start,end)` queries; deterministic tests. **Verification:** `./gradlew testDebugUnitTest spotlessCheck lint`. **Deliverables:** primitives, tests, traceability and evidence.

## Stable task acceptance criteria

- **BT-006-AC-01:** Money carries an explicit supported ISO 4217 code and signed 64-bit minor units. Zero and negative values round-trip unchanged; positive-expense validation remains an application rule. Public money input and arithmetic do not use `Double` or `Float`.
- **BT-006-AC-02:** Addition, subtraction, and any exposed negation use checked arithmetic. Overflow fails instead of wrapping, currency mismatch fails before arithmetic, and successful operations retain the currency code.
- **BT-006-AC-03:** Numeric money parsing takes explicit locale and currency inputs, consumes the entire input, honors locale separators, preserves exactly representable zero and negative values, and rejects malformed input, nonzero excess precision, fractional units for zero-decimal currencies, and `Long` overflow. It neither infers a locale currency nor rounds.
- **BT-006-AC-04:** Explicit local calendar boundaries and timezone produce UTC half-open intervals `[start,end)`. Tests cover inclusion/exclusion at endpoints, midnight, month/year turnover, leap day, and 23-hour/25-hour daylight-saving days by resolving each local boundary independently.
- **BT-006-AC-05:** Explicit day, week, month, and year period operations can produce the immediately adjacent prior calendar unit using the same supplied timezone and week-start input. Adjacency follows calendar boundaries rather than equal elapsed duration. Dashboard defaults and custom-period comparison remain outside this task.
- **BT-006-AC-06:** Time, ID, locale, and timezone choices are caller supplied. Fixed inputs produce deterministic results, and changing a supplied timezone affects only boundaries explicitly recalculated with that timezone; domain operations use no hidden system defaults or random UUID generation.
- **BT-006-AC-07:** Core code remains free of Android, Compose, Room, DataStore, networking, and telemetry dependencies, and existing architecture tests continue to pass.
