# BT-019: Make agent handoffs finite and enforce workflow phases

**Objective:** Reduce implementation latency by making the existing Planner → Tester red → Builder → Tester verify → Reviewer workflow explicit, enforceable, and finite.

**Inputs:** `AGENTS.md`, `workflow/README.md`, `docs/security-gates.md`, `.codex/agents/*.toml`, workflow scripts/templates/tests, and BT-005 evidence. **Allowed scope:** agent role contracts, workflow state/gate scripts, workflow documentation/templates, and their unit tests. **Out of scope:** Android production code, product behavior, specifications, ADRs, dependencies, CI, and weakening security or independent-review requirements.

**Acceptance:**

- **BT-019-AC-01:** Planner produces one persisted executable plan; Builder implements that plan without redesigning criteria, editing Tester-owned acceptance tests, or entering an automatic Planner loop.
- **BT-019-AC-02:** Every active workflow phase is represented by a legal transition, and gates reject skipped or out-of-order phases.
- **BT-019-AC-03:** Rework records a failure owner and stable fingerprint; the second identical unresolved failure blocks automatic handoff instead of repeating the loop.
- **BT-019-AC-04:** Tester has explicit red and post-build verification contracts, Reviewer only returns blocking findings to rework, and workflow tests cover the finite happy and repair paths.

**Required tests first:** Transition-order tests for the happy path and forbidden skips; gate/state alignment tests; rework ownership/fingerprint tests; second-identical-failure termination test; legacy completed-task compatibility. Record the red output before implementation.

**Verification:** `python3 -m unittest discover -s workflow/tests -p 'test_*.py' -v`, Python compilation, JSON/TOML parsing, and `python3 workflow/next_task.py`. Review all role contracts and workflow documentation for agreement with the executable state machine.

**Deliverables:** Minimal workflow/control-plane changes, updated agent contracts and templates, tests, traceability, and task evidence. No Android build is required because Android source and Gradle configuration are unchanged.
