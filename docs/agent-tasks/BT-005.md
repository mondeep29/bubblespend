# BT-005: Initialize native Android foundation

**Objective:** Create a clean-checkout Kotlin/Compose Android project with reproducible CI gates.

**Inputs:** ADR-001, ADR-002, product NFRs. **Allowed scope:** Gradle/Android project, app shell, CI, test fixtures, setup docs. **Out of scope:** expense feature behavior.

**Required tests first:** App startup, route, theme/semantics smoke, and architecture-boundary check. Capture red result before app shell. Lock exact dependency versions; add formatter, Android Lint, unit/UI test harness, debug build and CI. No unrelated upgrades.

**Acceptance criteria:**

- **BT-005-AC-01:** Launching the app opens the named home route with its accessible heading and configured theme semantics.
- **BT-005-AC-02:** Automated app startup and route smoke coverage passes on a representative Android emulator; its command is documented.
- **BT-005-AC-03:** Architecture checks prevent Android, Compose, Room, and DataStore dependencies from entering pure Kotlin domain/application modules.
- **BT-005-AC-04:** A clean checkout can run formatting, Android Lint, unit tests, and debug APK assembly using checked-in pinned tooling and CI configuration; the app has no global clock, ID generator, or database dependency.

**Verification:** `./gradlew spotlessCheck lint testDebugUnitTest assembleDebug`; `./gradlew connectedDebugAndroidTest` on a recorded emulator. **Deliverables:** source, tests, CI, setup instructions, evidence.
