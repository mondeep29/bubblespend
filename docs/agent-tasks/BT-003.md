# BT-003: Prove Android overlay and chart approach, then approve the overlay specification

**Objective:** Demonstrate the two high-risk platform interactions before production feature work, then complete independent SPEC-005 approval after all required proof.

**Inputs:** ADR-004, SPEC-005 draft, proof templates, D-01 and D-06 decisions. **Allowed scope:** disposable `spikes/`, `docs/proofs/`, ADR-004, SPEC-005, decision log, task evidence. **Out of scope:** production overlay feature.

**Required proof:** Run overlay scenarios listed in `docs/proofs/android-overlay.md` on an emulator and a real device; run accessible chart/list/drill-down proof in `docs/proofs/analytics-visuals.md`. Spike code may be discarded after evidence is recorded. No red test required for disposable proof, but automated tests should be added for reusable geometry/state rules.

**Acceptance:** Both proof files identify exact devices/versions, results, limitations, and a go/no-go recommendation. SPEC-005 is complete and Approved with independent reviewer evidence before task completion. **Verification:** actual emulator and real-device runs, accessible chart proof, and independent manual criterion/spec review. **Deliverables:** proof records, updated ADR-004 and decisions, approved SPEC-005, reviewer evidence, task evidence.

## Final documentation/spec approval phase

Only after the emulator and real-device overlay proof and accessible chart proof are recorded, complete and review SPEC-005 in this final phase; obtain independent reviewer approval before done/completion. This phase carries the full former BT-004 SPEC-005 obligation. Resolve D-01 and D-06 from evidence or an explicit product-owner decision; do not invent decisions. Complete every section of the spec template, including complete Given/When/Then criteria, errors, interruption behavior, privacy, accessibility, and an exact test plan. Map criteria to named verification and manual criterion review. No behavior-changing open question may remain. Record the independent reviewer evidence and verification result. Mark SPEC-005 `Approved` only after that independent approval. Before BT-003 completion, the coordinator must add the actually Approved `docs/specs/SPEC-005-floating-shortcut.md` to BT-003 `planner.approvedSpecs`; the completion gate validates the recorded spec status. A draft spec is not sufficient.
