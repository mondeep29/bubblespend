# BT-021: Tier planning and reduce repeated context loading

**Objective:** Match planning, research, review, and context loading to task risk while preserving the existing independent handoffs and gates.

**Dependencies:** BT-020. Workflow-control scope; disjoint from BT-006 Android/domain files.
**Kind:** foundation. **Risk floor:** elevated because policy affects security/review handoffs.
**Allowed scope:** `AGENTS.md`, `.codex/agents/*.toml`, `workflow/CONTEXT.md`, `workflow/research/**`, `workflow/record_plan.py`, `workflow/gate.py`, workflow docs/templates/tests, and BT-021 packet/evidence.
**Out of scope:** Android/product code, verification execution/caching, CI/dependencies, model migrations, and weakening red-before-green, security, or independent-review gates.

## Acceptance criteria

- **BT-021-AC-01:** Planner records the risk tier before work. Low-risk work uses a concise plan and skips external research unless a genuinely current or unknown fact is needed; elevated work retains the full source-linked plan and independent preflight; destructive work retains action-specific approval.
- **BT-021-AC-02:** Planner checks `workflow/research/<topic>.md` first. Entries record source URLs, access date, topic/version scope, and a 30-day freshness limit. Stale or version-mismatched material is not treated as current.
- **BT-021-AC-03:** `workflow/CONTEXT.md` contains a concise operational digest. Role contracts direct agents to it and task packets carry only the relevant approved spec excerpts/acceptance IDs, with full approved source docs remaining authoritative.
- **BT-021-AC-04:** Reviewer handoffs scope inspection to the diff/evidence and risk-relevant checklist; independent review remains mandatory. Agent contracts declare explicit model and reasoning settings where the project runner supports them, selected for role needs and documented without treating API token prices as Codex agent costs.
- **BT-021-AC-05:** A coordinator command persists a Planner response from stdin to the deterministic task plan path and updates JSON `planner.planPath` safely in one operation.
- **BT-021-AC-06:** Workflow guidance permits planning task N+1 during task N review and parallel work only for disjoint file ownership with an integration owner; dependent product work still follows its dependency chain.
- **BT-021-AC-07:** The active queue consolidates only pending BT-008 into BT-007, BT-013 into BT-011, and BT-018 into BT-017. All absorbed objectives, inputs, acceptance/proof obligations, verification commands, and prerequisite specs/ADRs are carried into the surviving packets in an explicit ordered slice; dependencies are redirected without bypassing approved-spec, chart/device proof, red-test, elevated preflight, independent review, or release gates. Absorbed IDs remain archived with absorbedInto metadata and are never recorded as done; migration validates source states and restores all changed queue/packet/gate files on failure.
